## 1. السياق

المشروع حالياً موقع ثابت من ثلاثة ملفات (`index.html`، `main.css`، `main.js`) بدون أدوات بناء ولا اختبارات. واجهته تتدرّج عبر ثلاث خطوات (قارئ ← رواية ← سورة) بطلب شبكة في كل خطوة، ومشغّل الصوت عنصر `<audio>` أصلي يقع في منتصف الصفحة فيختفي مع التمرير.

### 1.1 المشاكل المرصودة في الكود الحالي

| المشكلة | الموقع | الأثر |
|---|---|---|
| صور ضخمة | `image/*.jpg` | **15.5 م.ب** (6.6 + 8.9) تمنع فتح الموقع على شبكة ضعيفة |
| تصادم أسماء | `main.js:123` — `surahname` داخل `forEach` على `surahname` | سلوك غير متوقع |
| متغيّر ضمني عام | `main.js:119` — `surahname = data.suwar` بلا `const` | تلوّث النطاق العام |
| بناء DOM بـ O(n²) | `main.js:128` — `innerHTML +=` داخل حلقة على 241 عنصراً | إعادة تحليل الـ DOM كاملة في كل تكرار |
| بحث معطوب عملياً | `main.js:20` — `textContent.includes()` بلا تطبيع عربي | «احمد» لا يجد «أحمد»، «فاطمه» لا تجد «فاطمة» |
| تعارض CSS/JS | `main.css:318` `:nth-child(n+11){display:none}` ضد منطق «إظهار المزيد» | سلوك غير متوقع |
| شاشة ترحيب كاملة | `main.css:14` و `.video { height:100vh }` | **200vh قبل أي زر تفاعلي** |
| تبعية غير مثبّتة | `index.html:12` — `hls.js@latest` من CDN | لا ذاكرة مؤقتة، لا ضمان توافق |
| بلا معالجة أخطاء | كل استدعاءات `fetch` | فشل صامت |
| `lang="en"` | `index.html:2` | كاتب الشاشة والبحث في العربية على صفحة إنجليزية |
| تكرار شبكة | `main.js:117` يُعاد جلب السور في كل زيارة لقارئ | 12 ك.ب ضائعة كل مرة |

### 1.2 الأهداف

1. مشغّل صوتي عائم لا ينقطع الصوت عند التنقل بين الصفحات أو التبويبات.
2. التحكم الذكي: ±10 ثوانٍ، إعادة السورة، تشغيل تلقائي للسورة التالية.
3. تحويل الموقع إلى تطبيق ويب تقدّمي (PWA) يعمل بلا شبكة.
4. سرعة فتح فورية على شبكات ضعيفة.
5. وضع ليلي أساسي لمستمعي الليل وقبل النوم.
6. تصميم يركّز على الهاتف أولاً، بمستهدف مساحة لمس لا تقل عن 48 بكسل.
7. الوصول إلى أي سورة بأقل عدد نقرات.
8. تبويب «المفضلة» لحفظ السورة بصوت القارئ المطلوب.

### 1.3 خارج النطاق لهذه الجولة

- وضع القراءة/المصحف مع تظليل الآية (يبني على `ayat_timing` المدمج في التصميم لكنه مؤجَّل)
- تكرار الآية الواحدة (يتطلب نص الآية)
- مزامنة المفضلة عبر حساب
- إدارة قائمة تشغيل يدوية وإعادة ترتيب بالسحب
- الإشعارات الفورية (push notifications) والفهرسة الكاملة للعمل بلا شبكة (offline indexing)
- ترجمة واجهة

## 3. حقائق الواجهة البرمجية — تم التحقق منها فعلياً

الأساس: `https://mp3quran.net/api/v3` · بلا مصادقة · `Access-Control-Allow-Origin: *` على كل النقاط.

| النقطة | الحجم | المحتوى |
|---|---|---|
| `reciters?language=ar` | 191 ك.ب | **241 قارئاً · 287 تركيبة رواية** |
| `suwar?language=ar` | 12 ك.ب | 114 سورة + مكية/مدنية + رقم الصفحة |
| `riwayat?language=ar` | 2.4 ك.ب | 20 رواية |
| `radios?language=ar` | 38 ك.ب | **177 قناة بث** |

### 3.1 نتائج الفحص التي تحكم التصميم

1. **`moshaf.id` فريد عالمياً** — 287 قيمة مميّزة من 287 مدخلاً، بلا تكرار.
   ⇒ مفتاح المفضلة `${surahId}:${moshafId}` صالح، ولا نحتاج `reciterId` في المفتاح.
2. **`moshaf_type` شفرة مبهمة** — القيم الفعلية `11` (215 مرّة)، `222`، `213`، `121`، `131`… وليست `1/2/3` كما توثّق واجهة `api_2` القديمة.
   ⇒ **لا نعتمد على الرقم.** نستخرج أسلوب التلاوة من `moshaf.name` عبر مطابقة النص: «مرتل» ← مرتّل، «المجود» ← مجوّد، «المعلم» ← مُعلِّم. أي اسم لا يطابق يُعرض كما هو دون تصنيف.
3. **ملفات السور `Accept-Ranges: bytes`** ⇒ التقديم/التأخير يعمل.
4. **البث `Accept-Ranges: none`, `Content-Type: audio/mpeg`** ⇒ لا تقديم. التشغيل والإيقاف فقط.
5. **`surah_list` يختلف بين تركيبات القارئ الواحد** — ماهر المعيقلي مثلاً: `total=114` و`total=114` و`total=38`. ⇒ الطابور يُبنى من `moshaf` المختار لا من قائمة السور العامة.

### 3.2 بنية URL

```
السورة:  {moshaf.server}{surahId.padStart(3,'0')}.mp3   →  https://server6.mp3quran.net/akdr/001.mp3
البث:    {radio.url}                                    →  https://backup.qurango.net/radio/ibrahim_alakdar
```

## 5. محرك الصوت

هذا هو أعلى جزء مخاطرة في المشروع. القواعد غير قابلة للتفاوض:

```js
// engine.js — يُنشأ مرة واحدة عند التهيئة ولا يُستبدل أبداً
const el = document.createElement('audio');
el.preload = 'auto';
el.playsInline = true;
el.crossOrigin = 'anonymous';
document.body.append(el);
```

| القاعدة | السبب التقني |
|---|---|
| عنصر واحد للجلسة كاملة | إنشاء `new Audio()` لكل سورة يجعله المتصفح على الجوال **طلب صوت جديداً** فيُحظر التشغيل التلقائي |
| لا تمرير الصوت عبر `AudioContext` | النظام يعلّق السياق عند قفل الشاشة فيقتل الصوت بعد ثوانٍ |
| `play()` بعد أول لمسة فقط | بعد تفاعل المستخدم، تبديل `src` على العنصر نفسه يعمل بلا حظر |
| تسجيل `MediaSession` عند التهيئة | لا عند أول تشغيل — وإلا اختفت أزرار شاشة القفل |
| العنصر دائماً في الـ DOM | عنصر منفصل قد يُجمَّد عند إزالة مؤقتة |

### 5.1 واجهة `engine.js`

```js
play(item)          // { url, title, subtitle, kind:'surah'|'radio', seekable }
pause()
toggle()
seekBy(deltaSec)    // يتجاهل بهدوء إن كان !seekable
restart()
setVolume(v)
destroy()           // للاختبارات فقط
```

**الأحداث:** `track` · `play` · `pause` · `time` · `ended` · `loading` · `error`

**سلوك `ended`:** يطلق `queue.next()`. حاجز 400 بكسل يمنع التطاير المزدوج للحدث.

**سلوك `error`:** إعادة تحميل واحدة تلقائياً، ثم إطلاق `error` لعرض رسالة «تعذّر تحميل السورة» مع زر «تخطّي».

### 5.2 `mediaSession.js`

```
metadata = new MediaMetadata({ title, artist, album, artwork })
setActionHandler: play · pause · seekbackward(10) · seekforward(10)
                   previoustrack · nexttrack · stop
setPositionState({ duration, position, playbackRate })
playbackState: 'playing' | 'paused'
```

كل `setActionHandler` داخل `try/catch` مستقلاً — إجراءات غير مدعومة لا تُسقط الباقي.
تُحدَّث `metadata` عند كل تبدّع مسار لأن المتصفح يعيد استخدام آخر بيانات.

### 5.3 الطابور

```js
playlist = moshaf.surah_list.split(',')   // يحترم سور القارئ المتاحة
next()  → العنصر التالي، أو التوقّف عند النهاية
prev()  → العنصر السابق
```

`repeat: 'off' | 'one'` — `'one'` يعيد السورة الحالية فقط. عند نهاية الطابور مع `'off'` يتوقف التشغيل ويعرض حالة «انتهى».

### 6.1 شكل المخزن

```js
{
  theme: 'auto' | 'light' | 'dark',
  activeTab: 'reciters' | 'surahs' | 'favorites' | 'radio',
```

### 6.2 ما يُحفظ في `localStorage`

`theme` · `selectedMoshafId` · `repeat` · `volume` · `favorites` · `activeTab` · `cachedReciters` (بصلاحية 24 ساعة) · `cachedSuwar` · `cachedRadios` · `cachedRiwayat`

`191 + 12 + 38 + 2.4 = 243 ك.ب` من 5 م.ب ⇒ **4.9%** من المساحة. آمن.

### 6.3 تدفّق البيانات

```
تحميل الصفحة
  ├─ سكربت مضمّن في <head>: قراءة السمة من localStorage + prefers-color-scheme → data-theme  (قبل الرسم)
  ├─ قراءة الحالة المحفوظة → رسم الهيكل والمشغّل فوراً
  └─ جلب متوازٍ: reciters · suwar · riwayat · radios   (من الذاكرة المحلية إن كانت صالحة)
        └─ رسم شبكة القرّاء
             └─ اختيار قارئ → selectedMoshafId → جلب suwar (من الذاكرة) → رسم شبكة السور
                  └─ ضغط سورة → engine.play() + mediaSession.update() + store.patch()
                       └─ ended → queue.next() → engine.play()
```

## 7. التطبيع العربي

الهدف: أن يجد البحث «احمد» ← «أحمد» و«فاطمه» ← «فاطمة» و«يوسف» ← «يُوسُف».

```js
normalize('أحمد') === normalize('احمد') === normalize('أَحْمَد')   // 'احمد'
```

قواعد التطبيع بالترتيب:

1. حذف التشكيل: `U+064B–U+0652` و`U+0670`
2. حذف التطويل: `U+0640`
3. توحيد الألف: `أ إ آ ٱ ٲ ٳ ٵ` ← `ا`
4. الألف المقصورة ← الياء: `ى` ← `ي`
5. التاء المربوطة ← الهاء: `ة` ← `ه`
6. حاملتا الهمزة: `ؤ` ← `و`، `ئ` ← `ي`
7. حذف الهمزة المفردة `ء`
8. ضغط المسافات المتعددة ومسح الأطراف
9. تحويل الأرقام العربية-الهندية `٠-٩` ← `0-9`
10. تصغير الحروف اللاتينية

**قاعدة إلزامية:** يُطبَّق التطبيع **بنفس الإعدادات تماماً** على النص المفهرس وعلى استعلام المستخدم. أي اختلاف يُنتج فشلاً صامتاً.

**المطابقة:** استعلام متعدد الرموز بمنطق AND — كل رمز يجب أن يظهر في النص المُطبَّع. البحث يغطّي **القرّاء والسور معاً** ويعرض نتائج كل نوع في مجموعتها.

المساعدة تُكتب داخل المشروع بلا اعتماديات — الدوال نقية وتُختبَر بـ `vitest`.

## 8. الواجهة

### 8.1 التخطيط — خط أساس 360 بكسل

```
┌────────────────────────────────┐
│ قرآن الكريم           🌙  ⬇    │  شريط علوي ثابت · 56px
├────────────────────────────────┤
│ 🔍  ابحث عن سورة أو قارئ       │  يبحث القرّاء والسور معاً
├────────────────────────────────┤
│  القرّاء │ السور │ المفضلة │ البث │  4 تبويبات · كل منها ≥ 48px
├────────────────────────────────┤
│  ┌────────┐  ┌────────┐        │
│  │ الحصري │  │ السديس │        │  شبكة القرّاء
│  │ مرتّل  │  │ مجوّد  │        │  وسوم الرواية أسفل الاسم
│  └────────┘  └────────┘        │
│                                │
├────────────────────────────────┤
│ 18 · الكهف · الحصري        ♡   │  المشغّل العائم · fixed
│ ▓▓▓▓▓▓▓▓░░░░░░░░░  12:04       │  ↺  ⏮  ⏪  ▶  ⏩     (▶ = 64px)
└────────────────────────────────┘
```

- المشغّل `position: fixed` أسفل الشاشة. المساحة المخصّصة للعناصر تُضاف كـ `padding-bottom` على الحاوية حتى لا يُغطّي آخر بطاقة.
- عند فتح لوحة المفاتيح يرتفع المشغّل عبر `VisualViewport` API.
- في وضع البث: يعرض اسم القناة، ويتحكم بتشغيل/إيقاف والصوت فقط — بلا شريط تقدّم ولا ⏪⏩.
- زر القلب في المشغّل يبدّل تفضيل السورة **الجارية** بقارئها.

### 8.2 بطاقة السورة

عدّاد دائري لعدد الآيات على نمط المصحف التقليدي، اسم السورة، رقمها، وزر القلب.
البطاقة تعرض **السور المتاحة لدى القارئ المختار فقط**.

### 8.3 المفضلة

- المفتاح: `${surahId}:${moshafId}` (لأن `moshaf.id` فريد عالمياً)
- **زر القلب يبدّل**: إن كانت مضافة ⇒ تُزال، وإلا ⇒ تُضاف.
- كل مدخل يعرض اسم السورة واسم القارئ والرواية، لأن السورة نفسها قد تتكرر بأصوات مختلفة.
- زر «تشغيل الكل» في أعلى التبويب: يرتّب حسب رقم السورة، ويُشغّل تسلسلياً. السور غير المتاحة لدى قارئٍ ما تُتخطّى عند الوصول إليها.
- الحالة فارغة عند أول زيارة، مع شرح قصير وشريط «تصفّح السور».

### 8.4 الهوية بلا صور

- الخلفية: `rgb(40, 35, 35)` الحالية معزَّزة بتدرّج شعاعي ناعم — داكن دافئ، ليس أسود نقياً (راحة العين ليلاً).
- زخرفة هندسية إسلامية بصيغة SVG بشفافية منخفضة — أقل من 3 ك.ب، بلا أي ملف صورة.
- بلا شاشة ترحيب: الشريط العلوي والبحث والتبويبات ثم المحتوى مباشرة.
- الخط: **Amiri** (400 + 700 فقط) للنص القرآني واسم السورة، و**IBM Plex Sans Arabic** لواجهة الاستخدام — لأن Amiri غير مقروء في أحجام الواجهة الصغيرة.
- كل الخطوط مستضافة محلياً مع `font-display: swap`.
- `prefers-reduced-motion` مُحترم في كل الانتقالات.

## 10. PWA

استراتيجية لكل نوع مورد على حدة:

| المورد | الاستراتيجية | السبب |
|---|---|---|
| `request.mode === 'navigate'` | network-first بمهلة 3 ث + صفحة offline بديلة | الحداثة مقبولة هنا، والنسخة المحفوظة أفضل من شاشة خطأ |
| ملفات التطبيق (بصمة في الاسم) | cache-first، كاش بإصدار `shell-v3` | المحتوى لا يتغيّر إلا بتغيّر البصمة |
| JSON من mp3quran | stale-while-revalidate، 24 ساعة | الاستجابة فورية ثم تنعش في الخلفية |
| الخطوط | cache-first | ثابتة |
| **الصوت والفيديو** | **network-only** | لا نخزّن وسائط ضخمة |
| أي طريقة غير `GET` | لا يُتدخّل | لا إعادة تشغيل لطلبات غير آمنة للتكرار |

- كاش القشرة اسمه بإصدار ويُحذف في `activate` — **مع استثناء كاش البيانات الذي لا يُحذف**.
- `cache.addAll` ذرّي: فشل عنصر واحد يُبطل الكل ⇒ قائمة بـ precache قصيرة ومقصودة.
- `skipWaiting` **لا** يُستدعى بلا تفاعل. يظهر إشعار «يتوفر تحديث» وزر «تحديث» يحمّل الصفحة.
- `respondWith` تُستدعى بشكل متزامن في معالج `fetch`.
- بلا شبكة: شبكة القرّاء وشبكة السور والمفضلة تعمل من الذاكرة المحلية، مع شريط تنبيه انقطاع الشبكة.

## 12. الاختبار

**وحدات (`vitest`)** — دوال نقية بلا DOM:
- `utils/arabic.js`: 12 حالة تغطي الألف بأنواعه، الألف المقصورة، التاء المربوطة، التشكيل، التطويل، الأرقام، المسافات، والرموز المتعددة.
- `audio/queue.js`: السورة التالية/السابقة، احترام حد الطابور، احترام `surah_list` الناقصة، `repeat: 'one'`.
- مُقلّص المفضلة: الإضافة، الإزالة، مفتاح `${surahId}:${moshafId}`، منع التكرار، الترتيب حسب رقم السورة.

**يدوي (DevTools):**
- لوحة Application: تسجيل الـ SW، محتويات الكاش، اختبار Offline.
- Network: محاكاة Slow 3G وقياس LCP.
- فحص: لا أخطاء في الطرفية، لا طلبات فاشلة متكرّرة.

**جهاز حقيقي — Android Chrome (الأولوية العالية):**
- الصوت يستمر والشاشة مقفلة.
- الصوت يستمع والتطبيق في الخلفية.
- أزرار شاشة القفل: تشغيل/إيقاف/±10.
- أزرار سماعة الرأس.
- تبديل السورة تلقائياً والشاشة مقفلة.

**نشر:** التحقق من سلامة `base` على `gh-pages` ومن عمل التطبيق من مساره.
